# parcel_spod

Планировщик и основной пайплайн загрузки таблиц в СПОД.

## Кратко

Читает список объектов из Excel-расписания, для каждой таблицы: готовит данные в Greenplum (пользовательские SQL-функции), проверяет логи/объём, авторизуется в веб-СПОД через Selenium (с OTP) и запускает загрузку — целиком или порциями при объёме >6 млн строк. Работает как долгоживущий scheduler с очередью, обновлением сессии и вотчером Excel.

## Техстек

| Компонент | Технология |
|-----------|------------|
| Язык | Python 3.6.1 |
| UI-автоматизация | Selenium, Firefox, geckodriver |
| HTTP | requests (через общую OTP-сессию) |
| БД | Greenplum + SQLAlchemy |
| Конфиг / «UI» | Excel xlsx (`objects_scheduler.xlsx`) |
| Данные | pandas |
| Планировщик | schedule + threading / ThreadPoolExecutor |
| Auth | СУДИР + OTP; пароли через `noterball` |

## Ключевые GP-объекты

- `generate_temp_and_accum_tables` / `_big` — подготовка таблиц (< / > 6 млн строк)
- `logs_spod_func` — логи функций подготовки
- `logs_spod_process` — прогресс скрипта (`final_step`: 0/1/2…)

## Запуск (исторический)

См. `parcel_start.txt`. Нужны Python 3.6.1, Firefox + geckodriver, доступ к Greenplum, роль загрузчика в СПОД, сетевые диски/библиотеки окружения.

## Подробности по стадиям

Исходное подробное описание процесса (полный цикл, recovery при сбоях) сохранено в логике `main.py` и частично отражено ниже:

1. Чтение списка таблиц → проверка прогресса в `logs_spod_process`
2. Подготовка в GP (обычная / big-функция)
3. Проверки Success / нулевых изменений / поля `portion_spod`
4. Selenium: авторизация → структура → загрузка (целиком или по порциям)
5. Фиксация `final_step` и логи на объект в `logs/`
