# SPOD UI Automation

**Тип:** solo (самостоятельная разработка)  
**Контекст:** корпоративная автоматизация загрузки данных в СПОД (веб-интерфейс + API), без отдельного UI — управление через Excel-расписание и скрипты.

## Задача

Упростить и стабилизировать работу загрузчика СПОД: подготовка таблиц в Greenplum, запуск загрузок через веб/API, OTP-авторизация, мониторинг статусов и автоподтверждение загрузок.

## Состав набора

| Скрипт | Роль |
|--------|------|
| [parcel_spod](parcel_spod/) | Планировщик и пайплайн загрузки: Excel → GP-функции → Selenium/СПОД |
| [spod_otp_support](spod_otp_support/) | Поддержка OTP-сессии и cookies для остальных скриптов |
| [spod_check_status](spod_check_status/) | Мониторинг статусов загрузок, обновление логов в GP, уведомления |
| [spod_approve_load](spod_approve_load/) | Автоподтверждение готовых загрузок через API СПОД |

Типичный поток: **otp_support** держит сессию → **parcel_spod** готовит данные и ставит загрузки → **check_status** отслеживает прогресс → **approve_load** подтверждает.

## Общий техстек набора

- **Язык:** Python 3.6.1
- **Браузерная автоматизация:** Selenium + Firefox / geckodriver
- **HTTP:** requests (сессия по cookies после Selenium)
- **БД:** Greenplum через SQLAlchemy (`connectBD.use_new_engine`)
- **Данные/конфиг вместо UI:** Excel (xlsx) — расписание объектов, списки таблиц
- **Прочее:** pandas, schedule, threading; пользовательская библиотека `noterball` для расшифровки паролей

- Разбиение монолитной ручной работы на связанные сервисы/скрипты
