# AIWidgetSummary

AIWidgetSummary — специализированный агент подготовки текстового отчёта для объекта
«Мониторинг бизнеса УБ». Это не универсальный аналитический агент: логика, метаданные,
правила зон, промпты и структура итогового сообщения настроены под конкретный контур
виджетов УБ и формат управленческого отчёта.

## Минимальный стек

- Python 3.12: основной код агента, сбор evidence, маршрутизация шагов и постобработка.
- DatalabPRO / Jupyter Server: среда запуска и эксплуатации скрипта.
- ЛД Greenplum: источник данных, метаданные виджетов, промпты, политики и результаты. Промпты, `policy_json`, `axis_json` и зависимости хранятся как JSON-строки в таблицах.
- GigaChat API, модель `GigaChat-2-Max`: генерация текстовых выводов по виджетам, агрегация итогового отчёта и финальная вычитка.
- Собственная Python-оркестрация: LangChain и LangGraph не используются.
- Логирование и трассировка: лог приложения и JSONL-трасса с запросами/ответами LLM и промежуточными решениями.

## Основные таблицы

- `ai_os_ub_widget_meta`: метаданные виджетов, `axis_json`, `policy_json`, id промпта.
- `ai_os_ub_widget_field_meta`: описание полей виджета.
- `ai_os_ub_prompt_templates`: промпты агентов и output schema.
- `ai_os_ub_results`: сохранение пути к сформированному отчёту.
- `os_ub_nav`: источник фактических данных по виджетам.

## Поток обработки

1. Агент загружает список виджетов выбранной группы из `ai_os_ub_widget_meta`.
2. Для каждого виджета подтягивает последние версии данных из `os_ub_nav`.
3. `EvidenceBuilder` собирает evidence: факт/план, выполнение, зоны, переходы, недельную динамику и решение `should_write`.
4. `SummaryAgent` вызывает виджетовый промпт и формирует краткий вывод по одному показателю.
5. `FinalReportAgent` агрегирует выводы в итоговые разделы:
   - `Зона внимания`;
   - `Переход зон`;
   - `Динамика и Тренды`.
6. `FinalQualityAgent` выполняет финальную вычитку: формат чисел, месяцев, пустые подразделы и читаемость.
7. `ReportRenderer` сохраняет итоговый отчёт в текстовый файл.

## Особенности логики

- Раздел `Ключевые показатели` временно отключён: бывшие ключевые показатели живут по общим правилам попадания в `Динамика и Тренды`.
- `Зона внимания` строится детерминированно по red-зоне, чтобы LLM не мог потерять показатель.
- Внутри `Зоны внимания` есть подразделы `Цели` и `Фокусные метрики`.
- Фокусная метрика не превращается в цель: классификация берётся из `policy_json.attention_section`.
- Порог `attention_focus_pct_lt` влияет только на показ фокусной метрики в `Зоне внимания`.

## Промпты

Промпты не хранятся в коде. Они загружаются из `ai_os_ub_prompt_templates`:

- `template_id=1`, `DEFAULT_OS_UB`: вывод по одному виджету.
- `template_id=2`, `GROUP_FINAL_REPORT`: агрегация итогового отчёта по группе.
- `template_id=3`, `FINAL_QUALITY_REPORT`: финальная вычитка итогового текста.

## Токен и запуск

Токен GigaChat берётся из переменной окружения:

```bash
JPY_API_TOKEN
```

В `.env` токен не хранится.

Быстрая проверка:

```bash
pip install -r requirements.txt
python src/checks.py
python src/main.py
```

По умолчанию запрос идёт на:

```text
{GIGACHAT_BASE_URL}/chat/completions
```

Если нужен другой endpoint, задайте:

```bash
GIGACHAT_CHAT_URL=...
```

## Диагностика

Для каждого запуска формируются:

- лог приложения;
- JSONL-трасса с входами/выходами LLM;
- итоговый текстовый отчёт.

Трасса фиксирует ключевые промежуточные шаги: evidence по виджету, запрос и ответ
виджетового промпта, запрос и сырой/итоговый ответ групповой агрегации, запрос и
сырой/итоговый ответ финального проверятора. Это помогает понять, где именно
изменился или потерялся показатель.
