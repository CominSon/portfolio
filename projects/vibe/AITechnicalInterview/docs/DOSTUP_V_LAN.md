# Доступ к платформе с других компьютеров (локальная сеть)

Покупать хостинг не обязательно: можно крутить `./scripts/run-local.sh` на своём ПК и открывать сайт с ноутбука коллеги / телефона в той же Wi‑Fi или офисной сети.

## Что уже сделано в скрипте

- Backend слушает **0.0.0.0:8000** (не только localhost).
- Frontend (Vite) — **0.0.0.0:5173**.
- CORS при старте дополняется IP вашей машины в LAN (если удалось определить).

После запуска в терминале будут строки вида:

```
UI:    http://10.246.63.72:5173
API:   http://10.246.63.72:8000/docs
```

С другого ПК откройте **тот же адрес UI** (`http://ВАШ_IP:5173`).

## Настройка `.env` (рекомендуется)

Подставьте IP своей машины (из вывода `run-local.sh` или `hostname -I`):

```env
PUBLIC_BASE_URL=http://10.246.63.72:8000
CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173,http://10.246.63.72:5173
```

- **PUBLIC_BASE_URL** — ссылки на видео в письмах и API записей (иначе в письме будет `localhost`, с чужого ПК не откроется).
- **CORS_ORIGINS** — если браузер с другого ПК пишет ошибку CORS в консоли.

Ссылку кандидату на интервью давайте так:

`http://10.246.63.72:5173/interview/ТОКЕН_ИЗ_АДМИНКИ`

(не `localhost`).

## Файрвол (Linux)

Если с другого ПК «не открывается»:

```bash
sudo ufw allow 5173/tcp
sudo ufw allow 8000/tcp
# или временно отключить для проверки: sudo ufw disable
```

## Ограничение: камера и демонстрация экрана

Браузер разрешает **камеру, микрофон и захват экрана** только в «безопасном контексте»:

- `https://…`
- `http://localhost` / `127.0.0.1`

С **другого** компьютера по адресу `http://192.168.x.x:5173` Chrome/Edge часто **блокируют** `getUserMedia` / `getDisplayMedia` — интерфейс откроется, но запись не стартует.

**Что можно сделать:**

| Вариант | Сложность |
|---------|-----------|
| Кандидат на **этом же** ПК, где крутится сервер (`localhost:5173`) | Проще всего |
| HTTPS в локалке (самоподписанный сертификат + Vite `--https`) | Средне |
| Туннель ([ngrok](https://ngrok.com/), Cloudflare Tunnel) на время теста | Быстрый обход |

Для проверки **только UI и отчётов** с другого ПК HTTP достаточно. Для **полного интервью с видео** с чужой машины нужен HTTPS или туннель.

## Интернет снаружи (не только LAN)

Если Wi‑Fi **разные** (дом / офис / мобильный интернет) — LAN не поможет. Нужен **домен + туннель**:

→ **[DOMAIN_TUNNEL.md](DOMAIN_TUNNEL.md)** (Cloudflare Tunnel, HTTPS, камера с чужого ПК).

## Проверка

1. `./scripts/run-local.sh`
2. С телефона в той же Wi‑Fi: `http://IP:5173` — должна открыться главная.
3. `http://IP:8000/health` — ответ `{"status":"ok"}` или аналог.
