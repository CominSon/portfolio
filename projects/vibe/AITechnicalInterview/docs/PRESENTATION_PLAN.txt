ПЛАН ПРЕЗЕНТАЦИИ: AI Technical Interview Agent
Аудитория: руководство (бизнес + ИТ)
Формат: 12–15 минут + 5 минут Q&A
Дата подготовки: июль 2026

================================================================================
1. ЦЕЛЬ ПРЕЗЕНТАЦИИ (30 сек)
================================================================================
Показать, что у нас есть рабочий AI-агент для первичного технического
собеседования: без интервьюера-человека в комнате, с записью, стенограммой
и отчётом для HR/руководителя найма.

Ключевой месседж:
«Снимаем нагрузку с экспертов на первом фильтре, сохраняем прозрачность
оценки и артефакты (видео, код, отчёт).»

================================================================================
2. ЗАЧЕМ ЭТО НУЖНО БИЗНЕСУ (1,5–2 мин)
================================================================================
Проблемы, которые закрываем:
• Дефицит времени Senior/Lead на все первичные скрининги
• Разный уровень «строгости» у разных интервьюеров
• Нет единой записи «что спрашивали / что ответил / какой код»
• Долгий цикл до очной встречи с командой

Что даёт агент:
• Стандартизированный прогон по навыкам из вакансии (SQL, Python, …)
• Live Coding + Code Review в одном сценарии (~60 мин или короткий тест)
• Автоматический отчёт и ссылки на видео/стенограмму на почту HR
• Масштабирование: несколько кандидатов параллельно без слота эксперта

Не заменяет финальное очное собеседование — усиливает воронку на входе.

================================================================================
3. ИЗ ЧЕГО СОСТОИТ АГЕНТ (архитектура, 3–4 мин)
================================================================================
Слайд/схема «слои»:

[ Кандидат в браузере ]
  • Камера + микрофон + демонстрация экрана
  • Редактор кода (Monaco)
  • Диалог с AI-интервьюером + кнопка «Ответить»
        │
        ▼
[ Наш сервер (VPS) — FastAPI + React ]
  • Управление сессией интервью
  • Синхронизация редактора
  • Запись медиа-чанков → итоговое видео (ffmpeg)
  • Формирование отчёта и писем
        │
        ├──► LLM (DeepSeek) — «мозг» интервьюера:
        │      вопросы, оценка кода, план навыков, итоговый отчёт
        │
        ├──► Yandex SpeechKit STT — речь кандидата → текст
        │
        ├──► Yandex SpeechKit TTS — реплики агента → озвучка
        │
        └──► Почта (SMTP) — отчёт HR/заказчику

Кратко по ролям компонентов:
• DeepSeek — генерация вопросов, разбор кода, рекомендация hire/weak/reject
• Yandex STT — распознавание ответов вслух (русский, тех. лексика)
• Yandex TTS — голос агента (например, alena), спокойный темп
• FastAPI — оркестрация: когда спрашивать, когда писать в редактор, когда завершать
• Frontend — комната кандидата + админка для HR
• SQLite (сейчас на MVP) / записи на диске — сессии, банк вопросов, файлы видео

Важно для руководства: персональные данные и записи остаются на нашем контуре
сервера; облако используется для речи (Yandex) и рассуждений (DeepSeek),
не как «хранилище интервью».

================================================================================
4. КАК ЭТО РАБОТАЕТ ДЛЯ HR / КАНДИДАТА (3 мин)
================================================================================
Шаги HR (админка):
1) Подразделение + email для отчёта
2) Вакансия (+ опционально резюме) → агент извлекает языки/навыки
3) Подтверждение компетенций и весов
4) Формат: Live Coding / Code Review / комбинация; тест или полное ~60 мин
5) Ссылка кандидату

Шаги кандидата:
1) Открыл ссылку (HTTPS) → камера, микрофон, весь экран
2) Короткая проверка, что микрофон реально слышен
3) Агент задаёт вопросы голосом; код — в редакторе
4) Нажал «Ответить» → речь распознаётся, агент комментирует / даёт следующую задачу
5) Во время пауз (пока готовится озвучка) — короткий мини-тест (MCQ)
6) Завершение → монтаж видео + отчёт на почту

Артефакты для руководства после сессии:
• Текстовый отчёт с рекомендацией и оценками по навыкам
• MP4: экран + камера + звук
• Стенограмма диалога

================================================================================
5. КАКИЕ ВОПРОСЫ РЕШАЕТ И КАК (2–3 мин)
================================================================================
| Вопрос бизнеса              | Как решает агент                                      |
|-----------------------------|--------------------------------------------------------|
| Умеет ли SQL/Python на заявленном уровне? | Задачи в редакторе + устные пояснения, разбор кода |
| Не «вызубренные» общие фразы? | Конкретные сниппеты, follow-up по коду кандидата     |
| Честность / работа с незнанием? | Фиксируется в отчёте (honesty signals)              |
| Что происходило на собеседовании? | Видео + стенограмма + таймлайн кода                 |
| Кому слать результат?       | Настраиваемые email HR (только выбранные адреса)      |
| Быстрый смоук-тест без часа эксперта? | Режим «тест» (короткий прогон)                   |

Ограничения (честно сказать):
• Это скрининг, не замена deep-dive с командой
• Качество мини-теста MCQ дорабатывается (база проверенных вопросов + фильтры)
• Нужен доступ из сети кандидата (корпоративные firewall / домен / CDN)
• Оценка LLM — вероятностная; отчёт — решение для человека, не авто-оффер

6. ДЕМОНСТРАЦИЯ (2–3 мин, по возможности)
================================================================================
Вариант A (живой): короткая тестовая ссылка, 1 вопрос + кусок кода.
Вариант B (запись): 60–90 сек нарезки с экрана прошлого боевого интервью
  (без ПДн кандидата / с согласием).

Показать на экране:
• админку (создание ссылки)
• комнату кандидата (медиа ON, редактор, «Текущий вопрос»)
• пример отчёта / письма

7. ТЕКУЩИЙ СТАТУС И ROADMAP (1–2 мин)
================================================================================
Сделано (MVP в бою):
• Полный цикл: ссылка → интервью → видео → отчёт на почту
• Yandex STT/TTS + DeepSeek
• Live Coding + Code Review, тест/полный режим
• Проверка микрофона, ФИО в отчёте, SQL-задачи с sample-данными

В работе / ближайшие улучшения:
• Жёсткое качество мини-теста (проверенный банк вопросов, без «ложных» ключей)
• Устойчивость к корпоративным сетям (домен, HTTPS, при необходимости CDN)
• Дальнейшая калибровка сложности под Senior/Middle из вакансии

Метрики успеха для пилота (предложить руководству):
• Время эксперта на 1 кандидата до/после
• Доля кандидатов, дошедших до очного этапа
• Оценка HR: «хватает ли отчёта для решения go/no-go на следующий этап»
• NPS / обратная связь кандидатов по UX

10. ЗАПАСНЫЕ ОТВЕТЫ НА ВОПРОСЫ
================================================================================
Q: Почему Yandex, а не только «свой» whisper на сервере?
A: На VPS с ограниченной RAM облачный STT/TTS стабильнее по качеству русской
   тех. речи и не требует GPU; локальный whisper — запасной режим.

Q: Данные уходят в облако?
A: Аудиофрагменты — в SpeechKit для распознавания/озвучки; текст и логика
   диалога — в LLM API; записи интервью и БД — на нашем сервере.
   Детали — в политике ПДн пилота.

Q: Можно ли доверять оценке AI?
A: Для скрининга — да, как единообразный первичный фильтр. Финальное решение
   по найму — за человеком с опорой на отчёт и видео.

Q: Чем лучше асинхронного теста с таймером?
A: Живой диалог, код в редакторе, голос, запись экрана — ближе к реальному
   тех. интервью и сложнее «списать» пакетно.
